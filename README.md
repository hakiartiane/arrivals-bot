# Бот-рассылка о поступлениях

Клиенты подписываются командой `/start`, вы просто пишете боту сообщение —
и оно уходит всем подписчикам.

## Как это работает

- Клиент переходит по ссылке на бота и жмёт **Start** → добавляется в базу подписчиков (SQLite, файл `subscribers.db`)
- Клиент может отписаться командой `/stop`
- Вы (админ) пишете боту любое сообщение (текст, фото с подписью, документ) —
  бот пересылает его всем подписчикам и присылает вам отчёт: сколько отправлено, сколько не доставлено
- Команда `/stats` — узнать текущее количество подписчиков
- Команда `/export` — прислать вам CSV-файл со всеми подписчиками (chat_id, username, имя, дата подписки) — удобно для регулярного бэкапа базы
- Если у клиента бот заблокирован или аккаунт удалён — такой подписчик автоматически убирается из базы при следующей рассылке

## Шаг 1 — создать бота у BotFather

1. В Telegram откройте `@BotFather`
2. Отправьте `/newbot`, следуйте инструкциям, задайте имя (например "Поступления — Итан")
3. Получите **токен** — длинная строка вида `123456:ABC-DEF...`
4. Рекомендуется сразу поставить своё фото в качестве аватара бота через `/setuserpic` в BotFather — это то, что клиенты увидят при подписке

## Шаг 2 — узнать свой Telegram user ID

1. Напишите боту `@userinfobot` — он пришлёт ваш числовой ID
2. Это значение пойдёт в `ADMIN_ID`

## Шаг 3 — настроить переменные окружения

Скопируйте `.env.example` в `.env` и заполните:
```
BOT_TOKEN=токен_от_botfather
ADMIN_ID=ваш_id
```

## Шаг 4 — запуск

**Локально (для теста):**
```bash
pip install -r requirements.txt
python bot.py
```

**На хостинге (Render — постоянная работа 24/7):**

1. Загрузите эти файлы в GitHub-репозиторий
2. На Render.com нажмите **New → Web Service**, выберите этот репозиторий

   Важно: выбирайте именно **Web Service**, а не Background Worker — боту нужен открытый порт, чтобы UptimeRobot мог его пинговать (см. ниже)
3. Настройки сборки:
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `python bot.py`
4. В разделе **Environment** добавьте переменные `BOT_TOKEN` и `ADMIN_ID` (значение `PORT` Render подставит сам — ничего указывать не нужно)
5. Нажмите **Create Web Service** и дождитесь деплоя. После успешного запуска Render выдаст публичный адрес вида `https://ваш-бот.onrender.com`

**Подключение UptimeRobot:**

Бесплатный тариф Render "засыпает" после ~15 минут без запросов, а после этого бот перестаёт отвечать, пока не проснётся (десятки секунд задержки). UptimeRobot решает это, регулярно "стуча" в бота, имитируя живой трафик.

1. Зарегистрируйтесь на [uptimerobot.com](https://uptimerobot.com) (бесплатный тариф достаточен)
2. Нажмите **Add New Monitor**
3. Заполните:
   - Monitor Type: **HTTP(s)**
   - Friendly Name: любое, например "Broadcast bot"
   - URL: адрес, который выдал Render (например `https://ваш-бот.onrender.com`)
   - Monitoring Interval: **5 minutes** (в бесплатном тарифе UptimeRobot это минимальный шаг)
4. Сохраните — готово. UptimeRobot будет обращаться на этот адрес каждые 5 минут, получать в ответ `OK` от вашего бота и не давать Render усыпить сервис

Проверить, что health-check работает, можно просто открыв URL от Render в браузере — должна появиться надпись `OK`.

## Шаг 5 — приглашение клиентов

Отправьте клиентам сообщение вида:

> Чтобы получать уведомления о новых поступлениях первыми — подпишитесь на бота: t.me/ваш_бот_username
> Просто нажмите Start, и всё — рассылка будет приходить сюда.

## Важно

- Не рассылайте слишком часто (Telegram может расценить как спам при системном/агрессивном использовании) — 1-3 сообщения в день оптимально
- База подписчиков хранится в файле `subscribers.db` — если хотите сохранять её между деплоями на Render, используйте persistent disk (в бесплатном тарифе диск не сохраняется между рестартами)
- Чтобы не потерять базу при рестарте на бесплатном тарифе — периодически (например, раз в неделю) отправляйте боту `/export` и сохраняйте присланный CSV-файл у себя
